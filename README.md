# ColibriPipeline
Tools for Colibri data reduction and management for the three-telescope array
(REDBIRD / GREENBIRD / BLUEBIRD → Red / Green / Blue). The science goal is
detecting sub-second Kuiper-Belt-Object **occultation** events in ~40 Hz
photometry. Each telescope runs the same pipeline independently; some stages
then cross-correlate the three. The night-by-night orchestrator that chains the
stages lives in a **separate** repo
(`ColibriObservatory/PipelineAutomation/pipeline_automation.py`).

> **Module-level refactor in progress.** The pipeline is being reorganized into
> focused sibling packages that separate flow from I/O, photometry, archival,
> detection, and statistics — without changing outputs. See
> [.claude/refactoringPlan.md](.claude/refactoringPlan.md) (if present) and the
> "Package layout" section below. `detection/` is the first completed package;
> `colibri_io/`, `photometry/`, `archival/`, and `stats/` are scaffolded and
> being filled wave by wave.

## Environment / path configuration

Scripts are environment-aware. On a real telescope the base is `D:/`; for
development set:

```bash
export COLIBRI_ENV=sim
export COLIBRI_SIM_ROOT=/home/agirmen/research_data/ColibriPipelineSimulatedDirs
export COLIBRI_TELESCOPE=GREENBIRD        # -> uses <SIM_ROOT>/Green
```

Path resolution now lives in a **single source of truth**,
[ColibriPipeline/colibri_config.py](ColibriPipeline/colibri_config.py)
(`resolve_base_path`, `telescope_base_dirs`, `current_telescope`, plus the shared
datetime-format / site constants). The nine stage scripts and `colibri_tools.py`
call into it instead of each re-implementing the sim-vs-real block.

## Pipeline stages (run order)

The external orchestrator invokes these in order:

1. `colibri_main_py3.py` — primary detection: reads `.rcd` frames, SExtractor
   photometry (`sep`), runs the dip detector (`detection/`), writes per-minute
   `*_stars.npy` and `*_<sig>sig_pos.npy` into `ColibriArchive/<YYYY-MM-DD>/`.
2. `coordsfinder.py` — adds RA/Dec to detection txts via an astrometry.net plate
   solution.
3. `image_stats_dark.py`, `sensitivity.py` — per-night dark / sensitivity stats.
4. `wcsmatching.py` — WCS-matches stars; fills RA/Dec columns of `_pos.npy`.
5. `simultaneous_occults.py` — matches dip detections across the three
   telescopes by time + coords. **Green only.**
6. `colibri_secondary.py` — matches surviving candidates against occultation
   **kernels** and pulls star info (RA/Dec, mag) from Gaia.
7. `cumulative_stats.py`, `timeline.py` — nightly summary stats / operations
   plots. **Green only.**

Kernels for stage 6 are generated by `KernelGeneratorGUI_RAB032922/` (Rishi's
Fresnel-diffraction kernel generator; needs PySide2 — GUI, not headless).

## Package layout

Focused sibling packages (flat under `ColibriPipeline/`, mirroring the
`detection/` / `lightcurve_analysis/` convention):

| Package | Role |
|---------|------|
| `colibri_config.py` | env-aware paths + shared constants (single source of truth) |
| `colibri_tools.py`  | shared date/coord/detection-file helpers, `ErrorTracker` |
| `colibri_io/`       | RCD/FITS read, npy/det-txt I/O, Gaia query, astrometry.net + WCS *(filling)* |
| `photometry/`       | SEP star-finding, centroiding, aperture flux, drift *(filling)* |
| `archival/`         | per-minute light curves + mean stacks + `write_night_product` seam *(filling)* |
| `detection/`        | dip detection + multi-telescope coincidence/kernel matching *(done)* |
| `stats/`            | dark / sensitivity / cumulative stats + operations timeline *(filling)* |
| `lightcurve_analysis/` | night-scale npy visualizer (library + CLI + widget) |
| `detection_trade_study/` | offline detector comparison harness |

The Cython sources `colibri_image_reader.py`/`.pyx` and `colibri_photometry.py`/
`.pyx` stay in place (the `Init/` build scripts compile them on the telescopes);
the packages above wrap and re-export them.

## Supporting scripts

- `VizieR_query.py` — Gaia cone-search query (Jilly Ryan / Rachel Brown).
- `astrometrynet_funcs.py` — upload image to astrometry.net for a plate solution.
- `getRAdec.py` — pixel (x,y) → RA/Dec via an astrometry.net WCS.
- `getStarHour.py` — star-hours per observed field (used by `timeline.py`).
- `lightcurve_maker.py` — per-minute photometry → star light curves.
- `lightcurve_looker.py` — light-curve plots.
- `generate_specific_lightcurve.py` — synthetic light curves for missing scopes.
- `read_npy.py`, `snplots.py`, `bitconverter.py` — small I/O / plotting helpers.

## Other directories

- `Init/` — bash/batch files that compile the Cython modules.
- `PlotsAndPDFs/` — figures, usage manuals, presentations.
- `KernelGeneratorGUI_RAB032922/` — occultation-kernel generator (PySide2 GUI).

## Tests

```bash
cd ColibriPipeline
python -m pytest lightcurve_analysis/tests/test_smoke_sim.py   # smoke test (sim tree)
python -m pytest detection/tests/                              # detection package
```

Run via `python -m pytest` so they use the same interpreter (conda
`ColibriPipeline` env) that runs the pipeline. The `lightcurve_analysis` smoke
test sets `COLIBRI_ENV=sim` / `COLIBRI_SIM_ROOT` itself; Gaia (network)
assertions are soft.

## Dependencies

`pip install -r ColibriPipeline/requirements.txt` (numpy / scipy / astropy /
astroquery / pandas / sep / numba / Cython). `requirements-notebook.txt` adds the
optional ipywidgets/jupyter stack used only by the `lightcurve_analysis`
interactive explorer.
